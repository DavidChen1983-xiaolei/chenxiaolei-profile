## 一、视频口播的三条核心机制

| 机制 | 原意 | 本技能落地 |
|---|---|---|
| 跟着对话自己长 | 不要只写静态 TXT。在 skill 说明书里写清：每完成一个项目节点、改了一条工作注意事项、对文章润色提了新要求，临结束顺手让 AI 提炼偏好、原则并写回 skill 文件 | 设 6 类触发点，写 `evolution/LOG.md`，必要时更新 `references/profile.md` |
| 同机多 Agent 共用底稿 | Codex 建好后，把同一 skill 文件夹导入 WorkBuddy；云端 Agent 直接上传同一文件 | 本目录即唯一底稿，任何 Agent 读同一份 SKILL.md 与 references |
| GitHub 私有仓库跨端 | 当自带修改记录的云端私有文件夹；改一个标点也留快照；改乱可回退；换模型、换 harness、换电脑、换 Windows 或 macOS，连上 GitHub 就拿到积累 | `references/github-sync.md`；只 pull --rebase，禁 force push，推送前脱敏 |

视频原话要点：换 AI 或换电脑后认知归零，重复交代背景要返工三四遍、白耗 40 分钟；花 3 分钟建档案可让后续 1 分钟接手；GitHub 被比作自带修改记录的云端私有文件夹。

## 二、六类触发点

1. 项目节点完成或阶段性交付结束。
2. 用户改了一条工作注意事项。
3. 用户对润色、排版、措辞提出新要求。
4. 用户明确说以后都这样、默认按这个来、记住。
5. 同类纠正连续出现 2 次及以上。
6. 用户指出助手理解偏了个人习惯。

未触发时不主动改写档案。闲聊、单纯确认、纯转写不触发。

## 三、写回字段

每条进化记录固定 8 字段：

| 字段 | 说明 |
|---|---|
| id | `E-YYYYMMDD-NNN`，流水号 |
| time | ISO 日期时间 |
| trigger | 六类触发点之一 |
| raw | 用户原话摘录，≤ 100 字，脱敏 |
| distilled | 提炼后的规则，一句话，祈使句 |
| scope | 适用场景与不适用场景 |
| level | C1 已核 / C2 推断 / C3 待核 |
| target | 写入位置：`profile.md` 小节 / `style-writing.md` / `style-visual.md` / `workflows.md` / 仅日志 |

## 四、证据门槛

- 用户明说以后都这样：可记 C1，直接更新对应 reference。
- 同一偏好在 2 个不同任务中复现：可记 C2，先写日志，累计 3 次再更新 reference。
- 仅一次暗示、或助手自行观察：记 C3，只留日志，30 天后无复现则归档。
- 与用户级 `MEMORY.md` 硬规则冲突：不覆盖，先提示用户确认是否修订正本。
- 涉及学生真实身份、成绩、家庭情况：不写入任何文件，只记抽象规则。

## 五、写回动作

```bash
python ~/.workbuddy/skills/chenxiaolei-profile/scripts/append_evolution.py \
  --trigger "项目节点结束" \
  --raw "以后报告都按四环框架排" \
  --distilled "报告默认按四环框架排，方法与局限单列附录" \
  --scope "网页看板与研究报告；不适用于朋友圈短文案" \
  --level C1 \
  --target "workflows.md"
```

脚本写入 `evolution/LOG.md`，并按 `target` 提示需同步的 reference 小节。脚本不自动改写硬规则正本 `MEMORY.md`。

## 六、审计与回退

- `evolution/LOG.md` 追加写，禁止覆盖历史。
- 写回 `references/` 的增量必须一规则一条，不写复合句。同一目标文件的 `EVOLUTION-START` 块超过 20 条时，先把重复项合并回正文，再清空增量块；合并过程留一条 `MERGED` 日志。
- 每次更新 reference 前留commit粒度：一个小节一条提交，便于 GitHub 回退。
- 每月复核一次 C3 条目，无复现就标记归档。
- 发现错误规则：在日志追加 `SUPERSEDED` 记录，注明被哪条替代，不删旧行。
- 推送前跑 `scripts/redact_check.py`，命中敏感模式则禁止推送。

## 七、重构的创建提示词（C2）

> 请帮我创建一个个人档案 Skill。把我分散在历史对话、记忆和知识库里的身份、偏好、写作风格、视觉规范、常用工作流和边界，整理成一个可独立迁移的文件夹。要求：每次项目节点结束、我改了工作注意事项、或我对润色排版提了新要求时，顺手把要求提炼成规则并写回这个 Skill 的指定小节，同时留下带时间和证据等级的日志。不要只写一份静态自我介绍。让我在同一台电脑的多个 Agent 之间共用这份底稿，也能通过 GitHub 私有仓库跨设备同步和版本回退。凡是涉及学生真实姓名、成绩、家庭情况的内容，一律不得写入。
